SpawnLoft 1.5 puts a server's files in the panel: browse them, edit any text file beside the console, upload, download and tidy up, with a copy of everything changed kept in Backups.

- **Windows 10/11 x64:** download `SpawnLoft-Setup-1.5.0.exe`, signed through Microsoft Azure Artifact Signing.
- **Mac with Apple Silicon:** download `SpawnLoft-1.5.0-mac-arm64.dmg`.
- The Mac build is Developer ID signed, hardened, Apple-notarized and stapled. The app requires macOS 13 or later; managed MySQL requires macOS 15 or later.
- **Linux, Debian and Ubuntu (22.04+, Debian 12+):** `SpawnLoft-1.5.0-linux-amd64.deb`, or `-linux-arm64.deb` on arm64. Install with `sudo apt install ./<file>`.
- **Linux, Fedora, RHEL-family and openSUSE:** `SpawnLoft-1.5.0-linux-x86_64.rpm`, or `-linux-aarch64.rpm` on arm64. Install with `sudo dnf install ./<file>`.
- Java is separate on every platform, and which one depends on your Minecraft version. On Debian and Ubuntu: `sudo apt install openjdk-25-jre-headless`. On Fedora the newest is `sudo dnf install java-latest-openjdk-headless`.

Existing installs receive 1.5 through the built-in updater. ZIP files are used by the Mac updater; choose the DMG for a manual installation. A Linux install updates through a system password prompt, and takes the package of its own kind.

## New in 1.5

- **Files.** A server's folder is in the panel now, under Files in the dock. Open any text file in an editor that colours YAML, JSON and properties files and numbers its lines, and save it beside the console; upload by dropping files onto the list; download a file or a whole folder; rename, move, zip, unzip, and find anything by name. Every edit, replaced file and delete keeps a copy of what it changed first, and Backups can put back just that. A save over a file that changed since you opened it - the server rewrote it, or it was edited elsewhere - is refused rather than undoing that change, and a tab in YAML or broken JSON asks before it is saved. While the server runs, what it holds open - the active world, its jar, the plugins it loaded - cannot be moved, replaced or deleted.

- **Activity.** Every server has a history: what was done to it, when, and by whom - you, a scheduled task by name, an AI assistant by the name of its app, or SpawnLoft's own crash guard. Starts, stops and crashes, commands, backups, file and config edits, plugins, settings, worlds, players and schedules all appear, and can be narrowed to one kind of doer. A change that kept a copy of what it changed has Undo beside it, so "what did the assistant change last night" is one screen and one button. The Overview shows the last few things done on any server, and a line there opens that server's history. AI assistants can read it too, with `get_activity`.

- **Scheduled tasks can be several steps.** A task can now warn the players with a countdown, take a backup, and restart - in that order, in one run, each step waiting for the one before it, so a restart never overtakes its backup. Steps can also run commands, wait, verify backups, stop and start. A failed step stops the rest unless you say otherwise, and a task can be set to run only while the server is up. Three ready-made chains cover the usual nightly routines.

- **Backups you can keep, name and take with you.** Lock a backup and nothing deletes it - not the Delete button, not a schedule's retention - so the one taken before a big change stays. Give any backup a note ("before the 1.21 upgrade"), download it to keep somewhere else, and list paths each server's backups should leave out, such as a map plugin's rendered tiles. A restore can now clear what the backup holds first, so the server ends up exactly as it was; what was cleared is kept, so that can be undone too.

- **See how your server looks in the multiplayer list.** Settings shows the server's icon, name and message of the day the way players see them, with the colours; swatches insert Minecraft's colour and style codes, and any image becomes the server icon.
- **Java arguments of your own.** Settings, under Java and memory, keeps SpawnLoft's recommended flags unless you write your own, and shows the whole launch line either way. Memory stays with the Memory setting.
- **The console in its own window.** A button on the console's toolbar opens that server's console on its own - on a second screen, say - while the main window does something else.
- **Doctor notices a second copy of your data on Windows.** An AI assistant installed as a Windows package is given a private copy of what it writes under AppData, and the programs it starts read that copy from then on - so it can keep seeing the servers as they were the last time it wrote the registry - a server missing, a memory setting out of date - while its backups pile up where the Backups tab never looks. `spawnloft doctor` now finds the copy and says what differs and what to do about it, and the assistant is told at the start to ask you to run it outside the assistant, since a program that is itself redirected cannot see the difference. See [MCP.md](https://github.com/joogiebear/spawnloft/blob/main/MCP.md).
- **Move your data folder, and everything keeps working.** `spawnloft data move <folder>` moves SpawnLoft's whole data folder - servers, worlds, backups, the lot - to another place or another drive and leaves a link where it was, so nothing that points at the old path needs changing: not your servers' folders, not the databases, not the scheduled tasks. It shows what it would do first; on the same drive it is a single rename, and to another drive it copies, checks the copy and parks the original instead of deleting it until you say so with `spawnloft data finish`. Backup times are kept, and any failure puts everything back. On Windows it is also the lasting fix for an AI assistant reading a stale private copy of your data: a link that leads outside AppData is not redirected. See the README.
- **A clearer Overview.** What needs attention leads the page as a warning card with the button that fixes it. A stopped server says so in one line instead of a row of dashes, its button reads Start, Stop or Restart and shows when it is working, and a database only that server uses sits inside its card with an address you copy in one click. Recent activity sits beside the servers on a wide window and folds a run of the same thing - eighteen backups deleted in a minute - into one line that opens to show each. The summary at the top shows memory as a bar, and the sidebar lists servers and databases under their own headings.
- **Easier to read and to drive by keyboard.** The quietest text in the panel and the setup screen - console timestamps, line numbers, code comments in the file editor - is brighter, so it meets the WCAG AA contrast level in both colour schemes. The focus ring now appears the instant you press Tab, follows each control's own corners, and is the same ring on text fields and dropdowns as on buttons.
- **One set of controls across the panel.** Every button, field and tab is at least 32 pixels tall, so they are easier to hit and line up in a row. Tools show a placeholder while they load instead of a blank pane, and if one fails to load it says why with a Retry button. Hovering or tabbing to an icon button shows its name, notices carry an icon for success or failure, and empty lists for scheduled tasks and plugins offer the one action that fills them.
- **A sidebar you can read at a glance and drive from the keyboard.** A stopped server's dot is now a hollow ring and a running one a filled dot, so the two differ in shape as well as colour, and a database that is not answering shows red instead of grey. Redis-style caches get their own icon. The sidebar is a single Tab stop: the arrow keys move through servers and tools, Right opens a server or steps into its tools, and Left steps back out. Opening New server or Preferences no longer leaves the last server highlighted, and the New server button at the bottom is now a normal button that matches the one on Overview.
- **A clearer header on every server page.** Players, TPS and memory each get a live bar under the number, and the memory bar no longer runs into Last backup. A stopped server says so in a line instead of showing three dashes. The address now has a copy icon that turns into a tick when copied. Start, Stop and Restart show a spinner until the server answers, Stop is no longer red on every running server, and a database that runs elsewhere no longer shows a Start button that never works. In the ⋯ menu, Reset the world and Delete sit apart from the rest, in red.
- **A console that is easier to read and type into.** Long lines now wrap by default (the wrap button still turns it off, and the choice is remembered). Warning and error lines colour their level word as well as the bar beside them. When you scroll up, a "Jump to latest" pill appears above the input and counts the lines you have missed. The command box looks like a prompt, with the slash inside it, and pressing Down after Up brings back what you were typing instead of clearing it. Each server keeps its own command history while SpawnLoft is open. A stopped server offers Start server right in the command row, and databases no longer show a command box they cannot use.
- **Backups, Plugins and Files are easier to scan.** Backups opens with one line saying whether automatic backups are on, how many are kept, when the next runs and when the last whole backup was taken, and warns when there has been none for a week; when the schedule is off it offers Turn on nightly backups. Restoring names the snapshot you are about to put back. Every plugin shows its version and whether it is enabled, with Disable/Enable and Delete on each row, including plugins you added by hand. Files shows names in a fixed-width font, lines up sizes and dates on the right, and shows the full path when you hover a name.
- **Activity reads like the Overview feed, and Settings checks what you type.** A server's Activity is grouped by day, with an icon per kind of change and runs of the same thing (eight commands, three backups) folded into one line you can open. The filters are All, You, Schedule and Assistant, and Load more at the bottom fetches older entries. In Settings, a number outside its range or a webhook that is not a link says so under the field and Save waits until it is fixed, and the save bar only appears once something has changed.
- **Databases open on their connection details, and New server reads back what it will make.** Selecting a database now opens its page rather than an empty console: the engine, host and port as copy buttons, the admin login masked until you press Show (or Copy it without showing it), and the servers attached to it as links. The New server form is split into What to run and Who can join, shows the folder name a server would get before you type, checks the port as you type, says why versions could not load with a Try again button, and ends with one line summing up what Create will make. The sheet is titled Add a database on the database tab.
- **The first-run screen matches the panel.** Its buttons, folder fields and checkbox are the panel's own sizes, Continue is the panel's primary button, and a two-step indicator in the header shows you are choosing folders before the panel opens. The servers folder no longer runs into the Java check below it.
- **Screens hold still while they load.** The Overview waits for its first full answer before showing the server cards, so Needs attention no longer pushes them down as it arrives, and each server tab keeps its title row's place while loading or showing an error. An unreachable database says so on its own page with a Check again button instead of a red strip across the top. Backups list archives that record no scope as Unknown rather than a ? chip, Schedule tucks which system scheduler runs tasks behind How this runs, and the Players search is sized for names.
- **The Overview feed marks its days, and says when backup details could not load.** When the recent activity crosses midnight it is split under Today, Yesterday and dated labels. If the Overview cannot read backup ages and the machine's memory, it says so with a Try again button, and the cards say Backups unknown instead of waiting forever.

## Fixed

- A server whose backups had all been deleted showed "Last backup: Never" on the Overview, while its own activity listed the backups being made and deleted. It now says no backups are kept, and why: how many were deleted and when the backup schedule was removed.
- A backup of a running server could leave it with autosave switched off, if its world took longer than eight seconds to write out: the backup gave up on the flush, and with it on the step that turns saving back on. The flush now has two minutes, and the command that turns saving back on is sent whether the flush worked, failed or timed out. If the server does not confirm it, the backup says autosave may still be off and what to type - in the panel, in a scheduled task's log, on the command line and to an AI assistant.
- A few commands in every hundred sent to a server over RCON were hung up on, and the readings under a server's name - TPS and players online - dropped their connection and opened another again and again, each time writing two lines to the server's console. SpawnLoft sent a command and its end-of-reply marker back to back, and Minecraft's RCON thread hangs up on a read that holds two packets. The marker now follows the start of the reply, so the readings keep the one connection they were meant to, one-off commands stop leaning on retries, and a connection the server has closed fails at once instead of waiting out the timeout.
- A settings file that was cut off - by a crash or a full disk - or damaged by hand used to send SpawnLoft quietly back to its default data folder, where your servers were not: an empty list, or the first-run wizard, with no word of why. Settings are now written to a temporary file and renamed into place, so an interrupted write leaves the old file whole; a file that cannot be read is named on the command line, by `spawnloft doctor` and on the setup screen, with the way out; and SpawnLoft will not overwrite one it cannot read, since that would erase the folder it names - except when you choose a data folder yourself, in the wizard or with `config set-root`, where the damaged file is kept next to the new one, and its place is shown, instead of leaving you stuck.

SpawnLoft does not insert database credentials into plugin configuration files.


## Release build procedure

Maintainers build every platform from the same clean `main` commit. On the Windows Azure signing machine, on `main`, run `npm run release:stable` in `desktop`. It dispatches `desktop-stable`, which builds, signs, notarizes and exercises both native Mac apps, including an installed beta-to-stable upgrade, and builds both Linux architectures, installs the `.deb` with apt on Ubuntu 24.04 and the `.rpm` with dnf on Fedora, and exercises the installed app. Meanwhile it builds and signs the Windows installer, verifies it, runs the packaged-app smoke test and records its manifest; then it collects every platform's files in `desktop/dist/stable-release` and verifies them together.

`npm run release:stable -- --publish` then publishes. Publication checks all package bytes, Windows Authenticode, matching clean source commits, the successful native workflow, and the uploaded GitHub digests before exposing the complete release. Both beta and stable feeds are included so existing installations can move to stable.
