reading all of the code behind it, and once by running it and opening each state. Nothing in the code
was changed.

## How it was done

- **Read.** `src/ui.html` (14,386 lines), `src/launcher.html`, `src/setup.html`, the panel's API and
  core modules where they produce text a person sees, the Tauri shell and the Windows installer script.
  Four separate read-throughs, one per group of pages, each listing everything on the page before
  judging it.
- **Run.** The real panel against two test worlds: a plain one with no internet for error and offline
  states, and a rich one with five servers, three databases, players online, plugin updates waiting,
  backups, schedules and crash reports, where the download services were answered by stand-ins so that
  search, updates, version lists and creating a server worked. About 360 states opened at 800, 1100,
  1440 and 2560 wide, both themes at 1440. Part 5 says exactly what was real and what was a stand-in.
- **Check.** Findings from reading were tried in the running panel where the test worlds could reach
  them: 49 held (12 of them high) and 2 were wrong and were removed. About thirty high findings could
  not be tried here and rest on the code alone. A separate reviewer then checked about 155 findings
  against the code, including every one named on this page; seven had a wrong detail, now corrected,
  and none was overturned.

Not covered, and worth a session on your own PC: the real desktop window on Windows and macOS, a real
Minecraft server and game client, real MySQL, real monitors, and a screen reader.

Settled rules this scan does not reopen: the sidebar shell, "big screens show more, never bigger", the
density tiers, the two themes and the one-screen launcher.

Size: **S** is small, a few hours at most. **M** is about a day. **L** is several days or needs a
design decision first.

### Fix once, everywhere

These are patterns, each with one cause and many sightings. They are cheap for what they repair.

- **Keyboard focus is lost after almost every action**, because the page is rebuilt (X2, ACT9, PLY12,
  STA5, SCH17). Rebuild the row, or put focus back.
- **Escape closes the whole tool or sheet from inside a text box** (X3, PG9, PG10).
- **Explanations that exist only as a hover tooltip** on something a keyboard cannot reach (PG12, FI19,
  PLY16, B6).
- **A dialog that closes before it knows whether the input was valid**, so the typed text is lost and
  the error is a toast (X4, F3, LV6).
- **Controls with no name for a screen reader** (BK14, BK21, WO8, SCH13, PLY17, STA4).
- **Time written three ways** (A10, BK16, SCH19, OV5).

## What works and should stay

Each part ends its pages with a "Keep" list. The short version:

- The Overview answers "is everything all right?" in one look.
- The server header and the console are dense without being crowded, and the console's filter, counts
  and empty messages are right.
- Dangerous actions that do have a confirm usually have a good one: named, specific, typed where it
  matters (plugin delete, player data delete, version upgrade).
- Validation where it exists is inline and plain (Settings numbers, Add a server memory and port).
- The crash view gives a likely cause in ordinary words with a button to the right place.
- Backups puts "is this server backed up at all?" first and treats "no second copy" as a risk. (The
  answer it gives needs LV2 and BK6.)
- The launcher's blocked states each say what is wrong and link to the fix.
- Database passwords are masked until asked for, and external databases get no dead Start and Stop.
