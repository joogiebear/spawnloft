# UX scan, November 2026

A review of every screen on `v2` at 552082d: the panel (`src/ui.html`), the Play page and launcher
(`src/launcher.html`), the first-run wizard (`src/setup.html`), the sign-in and session pages, and the
Tauri shell and installer. Nothing in the code was changed.

How it was done: the panel was run against a scratch data root with three servers and a database, and
every page was looked at in a browser at 1100, 1440 and 2560 wide in both themes. All three HTML files and
the shell were also read in full. Each finding says how it was confirmed:

- **seen** means it was seen in the running panel.
- **code** means it was confirmed by reading the code only.

Not covered: the real desktop window on Windows and macOS, real monitors, and a screen reader. The
launcher's states past "Reading Mojang's version list" could not be reached in the test machine (no
network), so the launcher findings are from code.

Size: **S** is under an hour, **M** is about half a day, **L** is more.

Settled rules this scan does not reopen: the sidebar shell, "big screens show more, never bigger", the
density tiers, the two themes, and the one-screen launcher.

## Top recommendations

These are the ten that would change the most for the least work, in the order I would build them.

## A. Across the whole panel

**A1. Errors show raw technical text.** high, M, seen.
A failed request shows whatever arrived: `500 Internal Server Error`, the browser's `Failed to fetch`, or
in plugin search `could not reach Modrinth: getaddrinfo ENOTFOUND api.modrinth.com`. The plugin search
then adds "Nothing on Modrinth or Hangar matches that", which is untrue when the site was not reached.
`src/ui.html:3615`, `:7854`, `:6762`; launcher `src/launcher.html:1099`, `:2233`.
Fix: translate network failures and bare status codes in `api()` to one plain sentence, keep the server's
own sentence when it sent one, and show "Could not reach Modrinth. Check your connection." with Try again
in place of the empty result.

**A2. "Working on it" messages vanish after 5 seconds.** high, S, code.
Every non-error toast is removed after 5.2 seconds, including "Restoring…", "Uploading…", the mclo.gs
link and saved-file paths. Error toasts never expire and stack over the Send button (seen: the
Diagnostics toast covers Send).
`src/ui.html:3650`, `:11009`, `:9719`, `:6616`, `:2560`.
Fix: a toast option that stays until the job ends; keep any toast with a link or path until dismissed;
cap the stack and lift it above the command row.

**A3. Stop and Restart act at once, even with players online.** high, S, seen.
`src/ui.html:6677`, `:5757`; the confirm that already exists is at `:4519`.
Fix: reuse that confirm for Stop and Restart when players are online.

**A4. The page opens on "No servers yet" before the first answer.** high, M, code.
Everyone with servers sees the empty state flash, and it stays if the panel is not answering.
`src/ui.html:14366`, `:2801`.
Fix: start on "Loading your servers…".

**A5. "Lost contact with SpawnLoft" offers nothing to do.** high, M, code.
The banner has no button, and Start, Stop and Send stay enabled and then fail with A1's raw text.
`src/ui.html:5990`, `:6089`.
Fix: add Try again and a next step, and disable actions while contact is lost.

**A6. No force stop in the panel.** medium, L, code.
A server stuck on "Stopping…" has no way out, and the orphaned notice says
`Stop it with "spawnloft kill" in a terminal`. `src/ui.html:3975`, `:14324`.
Fix: a confirmed "Force stop" in the ⋯ menu and in both notices.

**A7. Buttons that look like plain text.** medium, M, seen.
Close (sheets), Change and Add a mirror (Backups), Create a database and Detach (Settings), Copy Claude
Desktop config and Copy diagnostics (Preferences) are borderless text with no hover hint at rest. Several
sit next to ordinary sentences and read as part of them.
Fix: give ghost buttons a visible resting shape (underline for inline links, a quiet border for actions).

**A8. Every tool opens with one or two lines of standing explanation.** low, M, seen.
For example "Everything in this server's folder. An edit, a replaced file or a delete keeps a copy first,
which Backups can put back." then "The server is running: files it holds open are marked In use…". They
are helpful once and then cost two rows on every visit.
Fix: keep the state line (running or stopped), and move the description behind a small "About this page".

**A9. Sidebar tooltip covers the first tool after you click a server.** low, S, seen.
The row's tooltip ("Survival with friends — Running") appears even when the name is not cut off, and sits
exactly over "Console". Fix: only show it when the name is truncated or in the icon rail.

**A10. Time and name formats differ between places.** low, S, code and seen.
The header says "LAST BACKUP now" where the page beside it says "just now"; "30h ago" in the header and
"1 day ago" on the card for the same backup. Toasts use the folder id ("Starting survival…") while every
other place shows the display name. Confirm dialogs title with the folder id too.
`src/ui.html:4342`, `:10283`, `:6660`, `:10997`.

**A11. Focus and announcements.** medium, M, code.
- "Open →" on Overview moves to the server page without moving focus (`:6320`).
- The shared dialog has no accessible name, and on destructive confirms focus starts on the red button so
  Enter confirms (`:3410`, `:3775`).
- Toasts are read twice by screen readers (`:3426`, `:3647`).
- Crash findings and state notices are not announced (`:2890`).
- Row actions in Backups and Players are faded to 45% and 60% until hover (`:1490`, `:1919`).
- Several controls are under the panel's own 32px minimum (`:971`, `:1042`, `:1057`, `:1200`).

## B. Backups and schedule

**B1. "Backup" and "snapshot" are the same thing.** medium, M, seen.
"Take a snapshot now, put one back…" sits above a "Back up now" button; the table column is "Snapshot";
Schedule says "Snapshots to keep"; dialogs say "Delete this snapshot?" for servers and "Delete this
backup?" for databases. `src/ui.html:10477`, `:10498`, `:8842`, `:11026`, `:12601`, `:4512`.
Fix: "backup" everywhere a user reads it.

**B2. Two controls for one switch on the Backups page.** medium, S, seen.
A strip says "Automatic backups off" with "Turn on nightly backups", and directly under it a card has an
Off switch, a frequency, a count and Apply. Flipping the switch does nothing until Apply is pressed.
`src/ui.html:10655`, `:10692`, `:10721`.
Fix: one card. The switch saves at once; frequency and count save on change.

**B3. The same backup warning three times on Overview.** medium, S, seen.
A server without backups gets a full-width "has never been backed up" card with two buttons, and its own
card repeats "Never backed up · Backups off · Set up backups". With three servers that is most of the
first screen. The attention cards also cannot be dismissed (`:5641`).
Fix: when the attention card is showing, drop the repeat in the server card, and allow dismissing.

**B4. Backups and Schedule overlap.** medium, M, seen.
Automatic backups are set on the Backups page, and "Take a backup" is also the first task type on the
Schedule page, which says "Nothing scheduled" while a nightly backup exists or not. It is not clear which
one is in charge.
Fix: show the backup schedule as a row on Schedule (linking to Backups), or say on each page where the
other lives.

**B5. Developer text under Automatic backups.** medium, S, seen.
"Runs with SpawnLoft closed while you are logged in. Daily and weekly jobs missed while the machine was
off run once when it is back; interval jobs skip missed runs. Tasks stop at logout unless lingering is on
for your account (loginctl enable-linger)."
Fix: "Backups run even when SpawnLoft is closed, as long as you are signed in to this computer." with the
rest behind "How this runs", as Schedule already does.

**B6. Row actions are unlabeled icons, and Restore is greyed with no visible reason.** medium, S, seen.
Lock, pencil and download have no text. Restore is disabled while the server runs and only a hover
tooltip says why, while the page says backups are "Safe while running". `src/ui.html:10923`.
Fix: one line above History ("Stop the server to restore") and labels or a ⋯ menu for the rest.

**B7. "Standard" and "mirror" are unexplained.** low, S, seen.
"No mirror: snapshots live on one drive, beside what they back up." is in code type and reads like a log
line. The mirror's off button is labelled "Off" (`:10806`).
Fix: "Backups are kept on the same drive as the server. Add a second copy on another drive."

**B8. Restore does not lock its row.** high, S, code.
While a restore runs nothing is disabled, so Restore or Delete can be pressed again. `src/ui.html:10986`.

**B9. Schedule details.** low, S, code.
A task missing from the system scheduler is labelled "Not in Windows" on Mac and Linux (`:9182`); recent
runs are listed by internal id and raw status (`:9141`); form labels are not tied to their fields
(`:8810`).

## What works well and should stay

- Not-running states explain themselves ("Not running. Start it to see players, TPS and memory.") and
  the command row swaps Send for Start server.
- Every tool has a skeleton while loading, an error with Retry, and an empty state with the one useful
  action.
- Destructive actions use one dialog with a named button and type-to-confirm, and say what copy is kept.
- The ⋯ menu's disabled items say why ("Stop the server first.").
- Status is rarely colour-only: stopped is a hollow ring, toasts and attention cards carry an icon.
- Sidebar keyboard handling, focus return from sheets, and one focus ring throughout.
- Settings: Changed and Default tags, dots on sections with edits, "Save and restart" only while running.
- Launcher: one sentence under Play says exactly what will happen, and a blocked Play names the reason.
- New server shows a clear message and Try again when the download service cannot be reached.
- Both themes hold up on every page checked; no horizontal overflow at 1100, 1440 or 2560.

## Note: Advanced Slime Paper "behind" but no update found

The panel has no "behind" notice for server software, so the message is most likely Advanced Slime
Paper's own start-up line in the console. SpawnLoft's check (Settings, Server software, Check for
updates) can disagree with it for these reasons, most likely first:

1. The build list is fetched once and kept for as long as SpawnLoft runs (`src/asp.mjs:17`). A build
   published since then is not seen until SpawnLoft restarts.
2. Only builds for the exact same Minecraft version count (`src/asp.mjs:40`); a newer Minecraft version
   shows as a separate line, or not at all (`src/upgrade.mjs:103`).
3. A jar SpawnLoft did not download is not checked (`src/upgrade.mjs:56`, `:76`).
4. The header and Plugins buttons are also called "Check for updates" and do not look at server software
   (E2).

Not verified against the live service, which the test machine could not reach.
